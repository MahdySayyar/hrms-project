# ADR-18 — بررسی سریع‌تر رمز با Argon2id و مهاجرت تدریجی

ثبت 2026-11-17، پیش از تغییر رفتار کد؛ review انسانی و Gate همچنان pending.

مسئله: ورود 500 حساب در شاهد ADR-17 حدود 107 ثانیه طول کشید؛ P95 نزدیک 100 ثانیه است. کاربر کاهش تأخیر و آماده‌سازی چند سرور مستقل را خواست؛ فعلاً فقط همین کامپیوتر موجود است. زیادکردن کانتینر CPU تازه ایجاد نمی‌کند. اندازه‌گیری جداگانهٔ رمز پیش از کد، هزینهٔ Argon2id را کمتر نشان داد؛ دو اجرای اکتشافی اولیه هم‌زمان بودند و برای مقایسهٔ ظرفیت قابل قبول نیستند. اجرای کنترل‌شده و آزمون HTTP مستقل لازم است.

گزینه‌ها: کاهش iteration فعلی PBKDF2، کش رمز/نتیجه، افزودن CPU واقعی، یا انتخاب KDF استاندارد مبتنی بر حافظه. کاهش iteration و کش نتیجه انتخاب نمی‌شوند. الگوریتم جدید Argon2id نسخهٔ 19 با حداقل پروفایل توصیه‌شدهٔ [OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html): 19456 KiB حافظه، time_cost=2، parallelism=1، salt مستقل 16 بایت و خروجی 32 بایت. تعداد workerها مستقل از parallelism خود الگوریتم است و با آزمایش انتخاب می‌شود. این مقایسه برابری ریاضی قدرت دو KDF را ادعا نمی‌کند؛ Argon2id دفاع مبتنی بر حافظه دارد و PBKDF2 قدیمی هنوز با iteration ذخیره‌شده بررسی می‌شود.

تصمیم: رمز حساب تازه/تغییریافته Argon2id شود. رمز قدیمی فقط بعد از بررسی موفق در صف خصوصی، به Argon2id تبدیل شود؛ plaintext ذخیره/کش نمی‌شود. ساخت hash جدید بیرون تراکنش DB است. پس از انتظار، CSRF و active/hash دوباره کنترل شوند و migration و login audit در همان تراکنش commit شوند. شکست audit یا تغییر هم‌زمان حساب هیچ hash جدید/نشست احراز‌شده‌ای باقی نگذارد. هزینهٔ اولین ورود legacy همچنان شامل PBKDF2 است. هیچ migration سراسری یا خواندن رمز واقعی اجرا نمی‌شود.

قراردادهای آزمون پیش از کد: TC-01-17 صحت/خطای رمز، salt مستقل، پروفایل Argon2id و PBKDF2 موجود؛ TC-01-18 migration موفق/رمز غلط/حساب تغییرکرده/rollback audit. صف bounded و پاسخ 503 قبلی حفظ می‌شوند. آزمون 500 حساب با saltهای مستقل، همان فرم/CSRF/cookie/audit/observer قبلی؛ نتیجهٔ password-only از HTTP جدا گزارش شود. کمتر از 1000ms برای P95 ورود هدف آزمون است و تا شاهد موفق، تضمین نمی‌شود.

اثر: dependency نسخه‌بندی‌شدهٔ argon2-cffi و memory budget معلوم؛ یک کار فعال 19MiB، چهار وب با دو worker حداکثر 152MiB حافظهٔ KDF فعال، صف شامل متن کوتاه درخواست و hash موجود است. مرز Domain/Service/Repository جدیدی ایجاد نمی‌شود. deployment تا شواهد پذیرش همان تنظیم فعلی است. downgrade داده بدون حفظ verifier Argon2id امن نیست؛ rollback باید پشتیبانی هر دو فرمت را حفظ کند.
