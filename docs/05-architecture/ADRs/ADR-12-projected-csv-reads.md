# ADR-12 — محدودکردن دادهٔ ورودی خروجی CSV

تاریخ 2026-11-17؛ طرح پیش از اصلاح کد همین گام، بازبینی انسانی در انتظار. رفتار CSV موجود از کد بازسازی شده است.

## مسئله و شاهد

`modules.export_employees` همهٔ Employeeها را به‌صورت ORM و `.all()` می‌خواند؛ ستون‌های کد ملی، تلفن و ایمیل نیز از DB دریافت می‌شوند، با اینکه در هشت ستون CSV نیستند. لیست همهٔ ردیف‌ها همراه StringIO و bytes پاسخ در حافظه است. نبود limit برای یک export کامل، به‌تنهایی خطای عملکرد نیست؛ materialization اضافی قابل اندازه‌گیری است.

## تصمیم و قرارداد

همان join، scope و ترتیب id، با projection دقیق هشت ستون خروجی اجرا شود. نتیجه با `yield_per=500` از cursor پایگاه خوانده و همان `csv.writer` استفاده شود؛ cursor پیش از audit و commit بسته شود. تعداد سطرها هنگام پیمایش شمرده شود. HTTP پاسخ کاملِ buffered باقی می‌ماند تا audit قبل از تحویل داده commit شود؛ این گام streaming response یا job async نیست.

بایت‌های CSV، UTF-8 BOM، عنوان‌ها، ترتیب، خنثی‌سازی فرمول، وضعیت فعال/غیرفعال، `Content-Disposition`، مجوز hr/admin و تعداد audit دقیقاً حفظ شوند. شکست audit نباید پاسخ موفق/CSV تحویل دهد. export خالی، بیش از یک batch و منع viewer/محدوده آزموده شوند.

## اثر و بازگشت

تغییر محدود در `app/modules.py`؛ FR-23، BR-03/04/14/21، UC-11 و API-11 مستند می‌شوند. schema و قرارداد خارجی عوض نمی‌شوند؛ مهاجرت داده یا deployment جدید لازم نیست. بازگشت همان query قبلی در snapshot است؛ داده‌ها و evidence قبلی نباید پاک شوند.

اندازه‌گیری حافظه با tracemalloc فقط allocation پایتون است، نه RSS کل سیستم. پاسخ نهایی هنوز O(N) بایت دارد؛ برای فایل‌های واقعاً بزرگ، سقف/streaming یا queue به طرح قرارداد، audit و مشاهدهٔ زمان/حافظهٔ واقعی نیاز دارند.
