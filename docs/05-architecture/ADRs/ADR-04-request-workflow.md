# ADR-04 — جداسازی گردش تصمیم درخواست

تاریخ: 2026-11-08. وضعیت هنگام ثبت: مشخص‌شده برای CR-01؛ تأیید انسانی هنوز ثبت نشده است.

مسئله: `review_request` اعتبارسنجی، چرخهٔ وضعیت، قفل‌گذاری، جست‌وجوی هم‌پوشانی، ثبت ممیزی و HTTP را کنار هم اجرا می‌کند. همچنین درخواستِ تغییر یک تصمیم نهایی به تصمیم مخالف، پاسخ 303 می‌گیرد؛ قرارداد UC-02 می‌خواهد این تعارض صریحاً با 409 رد شود.

گزینه‌ها:

| گزینه | فایده | هزینه |
|---|---|---|
| ادامهٔ منطق مستقیم در route | کمترین تغییر و خوانایی نسخهٔ مبتدی | آزمون مستقل قواعد و تشخیص تعارض دشوار می‌ماند |
| یک ماژول داخلی Domain → Service → Repository | قواعد وضعیت بدون HTTP/SQL آزمون می‌شوند؛ یک تراکنش و قفل‌های موجود حفظ می‌شود | چند فایل و یک مرز داخلی اضافه می‌شود |
| سرویس مستقل شبکه‌ای | امکان استقرار مستقل | شبکه، احراز هویت سرویس، شکست و تراکنش توزیع‌شده، بدون نیاز اندازه‌گیری‌شده |

تصمیم اجرایی: گزینهٔ دوم، فقط برای تصمیم درخواست‌های مرخصی، مأموریت و اداری. برنامه همچنان یک پردازه و یک PostgreSQL است. این تغییر ادعای تبدیل همهٔ پروژه به Modular Monolith ندارد.

Domain فقط نقش مجاز، قالب تصمیم و انتقال وضعیت را بررسی می‌کند. Repository فقط خواندن/نوشتن و قفل‌گذاری را انجام می‌دهد. Service ترتیب کار و تراکنش واحد تصمیم و audit را کنترل می‌کند. Route فرم و نشست را دریافت و خطای دامنه را به HTTP تبدیل می‌کند.

تکرار همان تصمیم، بدون نوشتن و ممیزی مجدد، به رکورد اصلی هدایت می‌شود. تصمیم مخالف پس از تأیید/رد، 409 می‌گیرد. قفل کارمند همچنان دو تأیید هم‌پوشان را سری می‌کند. شکست درج audit کل تصمیم را rollback می‌کند.

اعتبارسنجی: مشخصات [UC-02](../../../specs/UC-02.yaml)، آزمون‌های TC-02-01 تا TC-02-09 و آزمون مستقل وضعیت. نتایج قبل و بعد در `docs/08-testing/evidence/` ثبت می‌شوند. مسئلهٔ بار زیاد یا افزایش RPS هدف این تغییر نیست.
