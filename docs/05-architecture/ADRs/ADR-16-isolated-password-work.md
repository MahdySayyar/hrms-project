# ADR-16 — پاسخ‌گویی سایت هنگام صف ورود

2026-11-17؛ طرح پیش از کد اصلاح ورود؛ review انسانی و Gate بازند. [مبنای چهار وب](../../08-testing/evidence/login500-fourweb-before-20261117-a.json) با 500 پاسخ 303 و توزیع 125 ورود به هر وب، P95 ورود 90797ms، 43/56 probe timeout و restart صفر داشت. فقط افزایش وب‌ها صف thread و اتصال DBِ درگیر با hash را حل نکرد.

تصمیم: route ورود async می‌شود. CSRF ابتدا کنترل می‌شود؛ یک خواندن کوتاه snapshot شناسه/hash/active انجام و Session بسته می‌شود. PBKDF2 با همان 600000 iteration در executor خصوصی و bounded اجرا می‌شود؛ پیش‌فرض یک thread رمز در هر وب و حداکثر 512 کار پذیرفته‌شده، تنظیم مجاز 1..4 thread و pending بین تعداد thread و 512. صف async، thread عمومی وب و اتصال PostgreSQL را هنگام انتظار/محاسبه نگه نمی‌دارد. رمز، hash یا نتیجهٔ تطبیق cache نمی‌شوند.

پس از بررسی صحیح، CSRF/نشست دوباره کنترل می‌شود؛ حساب در تراکنش کوتاه دوباره خوانده و active و همان hash تأیید می‌شوند. فقط سپس audit commit و cookie/CSRF چرخانده می‌شوند. غیرفعال‌کردن، حذف یا تغییر رمز در حین انتظار به ورود با snapshot قدیمی منجر نمی‌شود. شکست commit نشست تازه نمی‌دهد. ورودی غلط 401 و CSRF نامعتبر/منقضی پس از انتظار 403 می‌مانند. پرشدن ظرفیت خصوصی 503 با پیام فارسی و Retry-After=2، بدون audit/ورود؛ این کنترل سقف کار CPU است و rate limiter جامع یا مقابلهٔ کامل با brute-force نیست.

اثر FR-01 و BR-01/02، UC-01، D-01 و مدل sequence/activity پیش از کد به صف، بازاعتبارسنجی و 503 ظرفیت اشاره می‌کنند. جدول/API/schema، قدرت hash و opaque cookie ثابت‌اند. helper runtime یک مرز Domain/Service/Repository تازه نیست. فقط تصمیم درخواست آن مرز را دارد. چهار وب با یک thread رمز در هر وب، حافظه/CPU صف را محدود و راه threadهای عمومی وب را باز می‌گذارند؛ زمان واقعی تکمیل 500 hash روی میزبان جداگانه گزارش می‌شود.

آزمون‌ها: رمز صحیح/غلط و نقش/CSRF قبلی؛ نبود اتصال checkoutشده هنگام hash؛ تغییر active/hash در همین فاصله؛ منقضی‌شدن نشست؛ شکست audit بدون ورود؛ ظرفیت پر و آزادشدن مجدد، اجرای محدود واقعی و زنده‌ماندن event loop؛ allowlist/مرز proxy. سپس همان 500 فرم آماده، barrier و probe و 500 نشست/audit با چهار وب تکرار می‌شود. تا قبولی، deployment اصلی تغییر نمی‌کند. mixed NFR پنج‌دقیقه‌ای، HA و خرابی worker هنوز پذیرش این گام نیستند.
