# ADR-01 — حفظ مبنای ساده و اصلاح تدریجی

تاریخ ثبت 2026-11-08؛ وضعیت: تصمیم اجرایی بازسازی‌شده، تأیید انسانی باز. منابع SRC-U01، SRC-C01 و اسلایدهای ۹/۳۹/۸۳ چارچوب و ۳/۱۲ آزمایشگاه.

مسئله: برای آموزش معماری، نسخهٔ کاربردی باید ساده و قابل مقایسه باشد. شروع با سیستم توزیع‌شده، علت تغییر و هزینه‌ها را پنهان می‌کند.

گزینه‌ها: A منطق مستقیم در مونولیت، B مرزهای داخلی برای همهٔ دامنه‌ها، C سرویس‌های مستقل. A استقرار و ردگیری ساده دارد ولی نگهداری دشوارتر است. B آزمون مستقل بهتر و انضباط بیشتر می‌خواهد. C استقرار مستقل می‌دهد ولی خرابی شبکه و هماهنگی داده اضافه می‌کند.

تصمیم: مبنای کاربردی A حفظ شود و هر مسئلهٔ مشاهده‌شده با ADR و نسخهٔ مستقل اصلاح شود. B فقط در تصمیم درخواست‌ها به کار رفته است. C تا وجود نیاز و آزمایش معتبر مطرح است.

نتیجه: baseline در commit 326f77b و snapshot مستقل محفوظ است. روش به هدف مستقیم کاربر وفادار است؛ هنوز ادعای اجرای کانتینر مشترک یا معماری کامل Modular Monolith نداریم. بازگشت کد از baseline ممکن است؛ برای بازگشت از migrationهای آینده باید بازیابی داده جدا طراحی شود.
