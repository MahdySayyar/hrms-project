# ADR-05 — خواندن محدود و صفحه‌بندی فهرست‌ها

تاریخ 2026-11-08؛ وضعیت: تصمیم پیش از اصلاح، پذیرش انسانی باز.

مسئله: با 10,000 پرونده و 50 کاربر، فهرست کارکنان timeout شد و CPU یک پردازهٔ وب نزدیک یک هسته پر بود؛ [EXP-00-CAPACITY](../experiments/EXP-00-capacity.md) محدودیت اجرای اکتشافی را هم ثبت می‌کند. route فعلی همهٔ پرونده‌ها را برای هر صفحه می‌خواند.

گزینه‌ها: افزایش RAM/timeout بدون کاهش کار؛ افزودن replica پیش از حل حجم هر پاسخ؛ محدودکردن خواندن در دیتابیس با pagination. ابتدا گزینهٔ سوم انتخاب شد چون تعداد ردیف‌های خوانده/نمایش‌داده‌شده را مستقیماً محدود می‌کند و با [UC-04](../../../specs/UC-04.yaml) قابل آزمون است.

طرح: helper مشترک PageRequest/Page، count پس از scope/filter، LIMIT/OFFSET و ترتیب ثابت؛ UI فارسی با شمارش کل و لینک‌های قبلی/بعدی. اندازهٔ پیش‌فرض 50 و سقف 100 است. صفحهٔ بزرگ‌تر از آخر، به آخر محدود می‌شود؛ ورودی نامعتبر 400. فهرست ماژول‌ها و فیش‌ها نیز همین قرارداد را خواهند داشت.

پیامد: count query اضافه می‌شود؛ OFFSET در صفحه‌های بسیار دور ممکن است هزینه‌بر باشد و حذف/درج هم‌زمان می‌تواند جابه‌جایی بین صفحات ایجاد کند. keyset pagination فقط پس از نیاز اندازه‌گیری‌شده بررسی می‌شود. تغییر به کل Modular Monolith یا حل تمام مسئلهٔ 500 کاربر نسبت داده نمی‌شود.

پذیرش فنی: مثبت/منفی/مرز/scope/filter در PostgreSQL واقعی؛ تکرار بار کنترل‌شده با همان 10,000 پرونده. گزارش قبل/بعد پس از اجرا تکمیل خواهد شد. Schema یا دادهٔ واقعی تغییر نمی‌کند.

ادامهٔ مجاز کاربر، 2026-11-12: تحمل 500 کاربر هم‌زمان هدف اجرای فعلی است. این ADR و UC-04 پیش از پیاده‌سازی صفحه‌بندی نوشته شده بودند؛ D-04، FR-06، BR-04 و CR-02 نیز پیش از کد این نوبت تکمیل می‌شوند. اجرای مقایسه و 500 کاربر و burst در schema مستقل با شواهد نام جدید انجام می‌شود؛ پذیرش انسانی باز است.
