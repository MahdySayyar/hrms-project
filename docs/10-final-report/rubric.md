# RUBRIC-01 — نسخه‌های معیار ارزیابی

دو جدول متفاوت در ارائه وجود دارد. مبنای کاری این گزارش، اسلایدهای 19 و 93 است چون Specification را جدا می‌سنجد؛ تأیید استاد برای انتخاب نهایی هنوز ثبت نشده است. برای پروژه نمرهٔ عددی تخمین زده نشده است.

| دسته | وزن نسخهٔ اسلاید 19/93 | شاهد HRMS و شرط باز |
|---|---|---|
| Problem & Requirements | 15٪ | منشور/FR/NFR/BR با منشأ؛ مصاحبه و review واقعی باز |
| Specification | 10٪ | FS-CAT و UC-01..03؛ پذیرش دانشجو باز |
| Analysis Models | 15٪ | Context/UC/Domain و 3 مجموعهٔ رفتاری؛ review باز |
| Architecture | 15٪ | alternatives، ADR و مرز محدود واقعی؛ آزمایش‌های scalability باقی |
| Detailed Design | 15٪ | component/class و schema/API استخراج‌شده؛ review انسانی باز |
| AI-assisted Transformation | 10٪ | 2 رکورد واقعی؛ human review و سوابق تاریخی کامل باز |
| Implementation | 10٪ | Core و 8 حوزهٔ HR؛ فقط یک مرز معماری استخراج شده |
| Testing & Validation | 5٪ | 29 آزمون و 98 assertion، coverage و load سبک؛ NFR کامل باز |
| Documentation & Traceability | 5٪ | ماتریس/اثر تغییر/گزارش و پیوند؛ ارزیابی شفاهی باز |

نسخهٔ اسلاید 61: Problem & Requirements 15٪، Analysis & Modeling 15٪، Architecture 15٪، Detailed Design 15٪، AI-Assisted Engineering 10٪، Implementation 10٪، Testing & Validation 10٪، Traceability 5٪، Documentation & Presentation 5٪. این نسخه Specification را جدا ندارد و Testing را 10٪ می‌سنجد. هر دو جمع 100٪ دارند؛ ترکیب آن‌ها یک جدول استاد محسوب نمی‌شود.

نمره‌های 90/95/… و 88.3 نمونهٔ UniFood در اسلاید 93 متعلق به HRMS نیست. جمع عددهای وزن‌دار نمایش‌داده‌شده در همان مثال 88.1 است؛ نمایش 88.3 ناسازگاری محاسباتیِ مثال است و به گزارش ما منتقل نمی‌شود. Consistency Score و نمرهٔ واقعی را reviewer باید از artifactهای پروژه تعیین کند.

پنج معیار سراسری اسلاید 59: Correctness، Completeness، Consistency، Traceability، Justification. کنترل link و test تنها بخشی از این ارزیابی است؛ توان دفاع و کامل بودن نیازها باید توسط انسان بررسی شود.
