# DEMO-01 — برنامهٔ ارائهٔ 15 دقیقه‌ای

ساختار زمانی مطابق [اسلاید 64](https://sadprojectdocs.space-z.ai/#slide-64). فایل PPTX نهایی و اجرای ارائهٔ دانشجو هنوز تهیه/ثبت نشده است؛ این سند برنامهٔ آمادهٔ ارائه است.

| زمان | بخش | چیزی که نشان می‌دهی |
|---|---|---|
| 0–1 | Problem | مسئله HR و هدف آموزشیِ تکامل معماری؛ CH-01 |
| 1–3 | Users & Requirements | نقش و scope، FR-13، BR-08/10/14، NFR پیشنهادی |
| 3–5 | Analysis Models | CTX-01، DM-01 و SEQ-02/ST-02 مطابق قرارداد واقعی |
| 5–7 | Architecture | مبنای ساده، سه گزینه و دلیل ADR-04؛ فقط ماژول تصمیم جدا شده |
| 7–9 | Detailed Design | Route/Domain/Service/Repository، transaction و lock order، API-02/DB-01 |
| 9–11 | AI Transformation | prompt/input/output واقعی؛ TRF-01 و TRF-02؛ review انسانیِ باز |
| 11–13 | Testing & Traceability | شکست 303/409 قبل، عبور بعد، concurrency/rollback، مسیر FR→code→test |
| 13–15 | Live Demo | ورود، درخواست ساختگی، تصمیم و نمایش نتیجه؛ سپس سناریوی تعارض |

دمو با schema مستقل و دادهٔ ساختگی آماده شود. روی پروندهٔ واقعی تصمیم استخدام/قرارداد/حقوق اعمال نکنید. UI تصمیم نهایی دکمهٔ تغییر دوباره ندارد؛ برای نمایش opposite retry، همان درخواست HTTP را با ابزار آزمون و CSRF معتبر در محیط آزمایش تکرار کنید، سپس 409 و رکورد/audit اولیه را نشان دهید.

سناریوی اصلی: HR وارد می‌شود، درخواست معتبر می‌سازد؛ admin تصمیم می‌دهد؛ detail و actor/time را نشان دهید. سناریوی استثنا: overlap مرخصی/مأموریت در روز مرزی یا opposite retry. برای حقوق، fixture آموزشی و snapshot پس از تغییر rule را از TC-03-01 نشان دهید.

تمرین Change Request استاد: مثال «بازگشایی تصمیم نهایی با دلیل» را ابتدا با FR/BR، UC، ST/SEQ، API، domain/service، audit/schema و tests تحلیل کنید؛ پیش از روشن شدن قرارداد کد را تغییر ندهید. این مثال صرفاً تمرین آینده است؛ ابلاغ واقعی استاد نیست.

پرسش‌های دفاع: چرا microservices انتخاب نشد؟ چرا lock employee علاوه بر request لازم است؟ audit failure چه می‌کند؟ retry چگونه از write دوباره جلوگیری می‌کند؟ نشست بین دو replica چه می‌شود؟ چرا load ده‌کاربری ظرفیت 500 را اثبات نمی‌کند؟ کدام artifactها بعداً بازسازی شده‌اند؟ کدام review انسانی هنوز باز است؟

پاسخ باید بر evidence تکیه کند. توضیح یادگیری و توان دفاع دانشجو توسط عامل قابل انجام یا تأیید نیست.
