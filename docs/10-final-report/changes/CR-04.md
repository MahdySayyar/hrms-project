# CR-04 — بازبینی معماری و اصلاح خواندن‌های موجود

2026-11-17؛ درخواست مستقیم کاربر برای بررسی کل محصول موجود، شواهد، ظرفیت با فرض‌های صریح و اصلاح کم‌ریسک. طرح این گام پیش از تغییر کد نوشته شده؛ معماری و رفتار قبلی از مخزن بازسازی شده‌اند. پذیرش انسانی/استاد ثبت نشده است.

## محدوده و ترتیب

1. snapshot جدید و آزمون مبنا؛ شکست اتصال اولیه جدا از شکست رفتار ثبت شود.
2. شمار SELECT فهرست‌ها، حافظه و بایت CSV و دورهٔ گزارش با schema مستقل و دادهٔ ساختگی ثبت شوند.
3. FR/BR، UC-04 و UC-11، مدل خواندن و ADR-11/12/13 پیش از کد به‌روز شوند.
4. اصلاح دسته‌ای نام منابع، projection/batch ورودی CSV و normalization دوره انجام شود.
5. آزمون مثبت/منفی/مرز، core PostgreSQL، coverage بخش تصمیم، engineering، Mermaid و pip check اجرا شوند.

## اثر تغییر و مهاجرت

schema، تراکنش‌های تصمیم/فیش، endpoint، session، قالب فارسی/RTL، وابستگی‌ها و topology عوض نمی‌شوند. CSV همچنان قبل از پاسخ audit می‌نویسد و buffered است. نام‌های منابع بین درخواست‌ها cache نمی‌شوند. فقط ورودی ماه با ارقام فارسی/عربی به جمع صحیح فیش وصل می‌شود. مهاجرت داده لازم نیست؛ برای بارگذاری source جدید restart/build معمول لازم است و restart نشست‌های حافظه‌ای را از بین می‌برد. تغییر استقرار زنده در دامنهٔ این اصلاح نیست.

ایندکس جدید، Redis، worker، gateway، replication یا sharding بدون شاهد بار و طرح مهاجرت اجرا نمی‌شوند. شرط هر پیشنهاد در گزارش معماری جاری ثبت خواهد شد. بازگشت هر اصلاح از snapshot فقط با patch همان بخش انجام شود؛ reset کل working tree و حذف تغییرهای پیشین مجاز نیست.
